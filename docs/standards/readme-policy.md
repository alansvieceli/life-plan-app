# README Policy

The README must be updated whenever a change affects:

- project setup
- installation commands
- development commands
- test commands
- build commands
- folder structure
- app behavior
- environment variables
- dependencies

## Quality Bar

The README should be practical, clear, and useful for someone opening the project without context.

It should be richer than a command list, while still avoiding unnecessary detail.

Maintain sections for:

- project purpose
- current app behavior
- setup requirements
- install commands
- development commands
- validation/test commands
- local data/storage behavior
- project workflow or contribution rules when relevant
- roadmap or known future work when it helps explain scope

## Rules

- Do not document features that are not implemented unless they are clearly marked as planned or future work.
- Keep commands copy-pasteable.
- Prefer short explanations and focused bullet lists.
- Keep the README aligned with the active specs and implemented behavior.
- If a change adds, removes, or renames a command, dependency, workflow, or user-visible behavior, update the README in the same task.
